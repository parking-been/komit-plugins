# 보안 검사

일곱 갈래로 나눠 본다. **접근 제어부터 본다.** 실제 사고의 대부분이 거기서 난다.

문제를 적을 때마다 다시 확인한다.

- 파일 경로와 줄 번호를 못 대면 적지 않는다
- 코드에서 보이지 않으면 「확인하지 못한 영역」으로 넘긴다
- 용어가 아니라 **무슨 일이 생기는지**를 쓴다

---

## 심각도 표

**여기 적힌 값을 그대로 쓴다.** 다시 판단하지 않는다.

| 그룹 | 항목 | 심각도 |
| --- | --- | --- |
| 접근 제어 | 개인정보나 남의 자료가 열린다 | `HIGH` |
| 접근 제어 | 관리자 기능이 열린다 | `HIGH` |
| 접근 제어 | 권한 확인은 있으나 빈틈이 있다 | `MEDIUM` |
| 비밀 관리 | 관리 권한 열쇠나 결제 열쇠가 노출된다 | `HIGH` |
| 비밀 관리 | 노출 범위가 제한적이거나 개발용 값이다 | `MEDIUM` |
| 입력 처리 | 자료를 꺼내거나 고칠 수 있다 | `HIGH` |
| 입력 처리 | 서버에서 뭔가 실행할 수 있다 | `HIGH` |
| 입력 처리 | 영향 범위가 한 화면에 그친다 | `MEDIUM` |
| 인증·세션 | 비밀번호를 그대로 저장한다 | `HIGH` |
| 인증·세션 | 인증표의 서명이나 기한을 확인하지 않는다 | `HIGH` |
| 인증·세션 | **인증표를 위조할 수 있다** | **`HIGH`** |
| 인증·세션 | 되돌리기 쉬운 방식으로 비밀번호를 바꾼다 | `MEDIUM` |
| 인증·세션 | 시도 횟수 제한이 없다 | `MEDIUM` |
| 인증·세션 | 로그아웃할 때 세션을 무효화하지 않는다 | `MEDIUM` |
| 설정 | 오류로 열쇠나 개인정보가 나온다 | `HIGH` |
| 설정 | 그 밖의 설정 문제 | `MEDIUM` |
| 개인정보 암호화 | 전부 | `HIGH` |
| AI 기능 | AI 답으로 돈 · 권한 · 자료가 바뀐다. 열쇠나 개인정보가 브라우저로 나간다 | `HIGH` |
| AI 기능 | 지시문만 드러난다. 도구 제한이 느슨하다 | `MEDIUM` |

**인증표 위조**는 놓치기 쉽다. 쿠키나 저장소에 사용자 번호를 그대로 담고 서명이나 암호화를 하지 않으면, 그 값을 바꿔서 다른 사람이나 운영자가 될 수 있다. 로그인 확인 코드가 있어도 소용없다.

**개인정보 암호화는 전부 `HIGH`다.** 법이 요구하는 항목이고 유출되면 되돌릴 수 없다. 되돌리기 쉬운 해시라도 대상이 비밀번호·주민등록번호·계좌번호·카드번호면 `HIGH`로 올린다.

## 1. 접근 제어

가장 흔하고 가장 크다. 인증은 "누구인지 아는 것", 인가는 "그럴 자격이 있는지 보는 것"이다. **인가가 훨씬 자주 빠진다.**

### 볼 것

| 무엇 | 어떻게 찾나 |
| --- | --- |
| 관리자·내부 경로에 인증이 없다 | `admin`, `internal`, `manage` 가 든 경로를 모두 찾아 인증 확인이 있는지 본다 |
| 남의 것을 볼 수 있다 | 주소에 식별자를 받는 경로에서, 그 자원이 요청한 사람 것인지 확인하는 코드가 있는지 본다 |
| 화면에서만 가렸다 | 버튼을 숨기는 조건은 있는데 서버 쪽에 같은 조건이 없는 경우 |
| 미들웨어를 건너뛴다 | 미들웨어가 막는 경로와 실제 처리 경로가 어긋나는 경우 |
| 요청한 값을 그대로 믿는다 | 요청 본문의 권한·역할·소유자 값을 검증 없이 쓰는 경우 |

### 읽을 곳

라우트와 핸들러 전부, 미들웨어, 인증 관련 코드, 관리자 화면.

### 이렇게 쓴다

```
좋음  누구나 회원정보를 볼 수 있습니다
      로그인 없이 관리자 주소로 들어가면 회원 목록이 그대로 열립니다

좋음  남의 주문 내역을 볼 수 있습니다
      주소의 숫자만 바꾸면 다른 사람 주문이 열립니다

나쁨  Broken Access Control (OWASP A01)
나쁨  IDOR 취약점. 인가 검증 누락
```

### 심각도

| | |
| --- | --- |
| `HIGH` | 개인정보나 남의 자료가 열린다. 관리자 기능이 열린다 |
| `MEDIUM` | 권한 확인은 있으나 빈틈이 있다 |

## 2. 비밀 관리

### 볼 것

| 무엇 | 어떻게 찾나 |
| --- | --- |
| 관리 열쇠가 브라우저로 나간다 | 관리자용 열쇠를 화면 코드에서 쓰는지 본다 |
| 공개 접두어에 비밀값 | 브라우저로 내려가는 환경변수 이름에 비밀값이 들어 있는지 본다 |
| 환경변수 파일이 저장소에 있다 | `.env` 류가 무시 목록에 없고 저장소에 들어 있는지 본다 |
| 열쇠가 코드에 박혀 있다 | 긴 무작위 문자열이 코드에 그대로 있는지 본다 |
| 개발용과 운영용을 섞어 쓴다 | 테스트 열쇠와 운영 열쇠가 같은 곳에 있는지 본다 |

**주의** — 실제 열쇠 값을 결과 파일에 옮겨 적지 않는다. 위치와 변수 이름만 적는다.

### 이렇게 쓴다

```
좋음  설정 파일에서 열쇠 지우기
      관리자 권한 열쇠가 브라우저로 내려가는 코드에 들어 있습니다

좋음  비밀번호가 담긴 설정 파일이 저장소에 올라가 있습니다
      저장소를 볼 수 있는 사람은 누구나 볼 수 있습니다

나쁨  Hardcoded credentials detected
나쁨  NEXT_PUBLIC_ 접두어 오용
```

### 심각도

| | |
| --- | --- |
| `HIGH` | 관리 권한 열쇠나 결제 열쇠가 노출된다 |
| `MEDIUM` | 노출 범위가 제한적이거나 개발용 값이다 |

## 3. 입력 처리

### 볼 것

| 무엇 | 어떻게 찾나 |
| --- | --- |
| 질의문을 문자열로 이어 붙인다 | 사용자 입력을 그대로 넣어 질의문을 만드는 곳 |
| 받은 글을 화면에 그대로 넣는다 | `dangerouslySetInnerHTML` · `innerHTML` · `outerHTML` · `document.write` · `v-html` · `bypassSecurityTrustHtml` · `[innerHTML]` 을 모두 찾아, 들어가는 값이 사용자 입력·주소·저장된 글에서 오는지 본다. 화면 코드도 반드시 본다 |
| 올린 파일을 확인하지 않는다 | 종류·크기 확인 없이 저장하는 곳. 저장한 곳이 공개인지도 본다 |
| 서버가 사용자가 준 주소로 요청한다 | 입력받은 주소로 서버가 내부 요청을 보내는 곳 |
| 아무 데로나 보내준다 | `redirect(` · `router.push(` · `res.redirect` · `location.href =` · `window.open(` 에 주소 매개변수(`next` · `returnTo` · `url` · `to`)가 그대로 들어가는 곳. 허용 목록이 있어도 "포함하는가"로만 비교하면 뚫린다 |
| 받은 값의 모양을 확인하지 않는다 | 요청 본문을 확인 없이 그대로 쓰는 곳 |
| 서버에서 받은 글을 코드로 실행한다 | `eval` · `new Function` · `vm.run*` · 템플릿 엔진에 사용자 글을 넣는 곳 · 문자열로 만든 셸 명령 |

### 읽을 곳

서버 경로와 핸들러, **그리고 화면 코드**(컴포넌트 · 페이지 · 템플릿). 받은 글을 심는 문제는 대부분 화면 쪽에 있다.

### 이렇게 쓴다

```
좋음  검색창으로 남의 정보를 꺼낼 수 있습니다
      검색어에 특정한 글자를 넣으면 다른 사람 자료가 나옵니다

좋음  올린 파일을 확인하지 않습니다
      그림 대신 실행되는 파일을 올릴 수 있습니다

나쁨  SQL Injection 가능
나쁨  XSS 취약점 존재
```

### 심각도

| | |
| --- | --- |
| `HIGH` | 자료를 꺼내거나 고칠 수 있다. 서버에서 뭔가 실행할 수 있다 |
| `MEDIUM` | 영향 범위가 한 화면에 그친다 |

## 4. 인증과 세션

자체로 만든 로그인에서 특히 많이 나온다. 외부 로그인 서비스를 쓰면 대부분 해당 없다.

### 볼 것

| 무엇 | 어떻게 찾나 |
| --- | --- |
| 비밀번호를 그대로 저장한다 | 저장 전에 되돌릴 수 없게 바꾸는 처리가 있는지 본다 |
| 표를 확인하지 않는다 | 받은 인증표의 서명과 기한을 확인하는 코드가 있는지 본다 |
| 표를 브라우저 저장소에 둔다 | 다른 코드가 읽을 수 있는 곳에 인증표를 두는지 본다 |
| 시도 횟수 제한이 없다 | 로그인과 인증번호 확인에 횟수 제한이 있는지 본다 |
| 나가도 그대로다 | 로그아웃할 때 서버 쪽 기록을 지우는지 본다 |
| 다른 사이트가 대신 요청을 보낼 수 있다 | 쿠키로 로그인하는데, 자료를 바꾸는 요청(글쓰기 · 정보 수정 · 결제 · 삭제)에 출처 확인이나 요청 토큰이 없고 쿠키가 `sameSite` 없이 또는 `none` 으로 설정된 경우. `lax` 라도 `GET` 으로 자료를 바꾸는 경로가 있으면 해당한다. `strict` 이거나 요청 토큰을 확인하면 적지 않는다 |

### 이렇게 쓴다

```
좋음  비밀번호가 그대로 저장되고 있습니다
      자료가 새면 회원들의 비밀번호가 그대로 드러납니다

좋음  로그인 시도 횟수에 제한이 없습니다
      비밀번호를 계속 넣어보면 언젠가 뚫립니다

나쁨  평문 패스워드 저장. bcrypt 미적용
나쁨  Rate limiting 부재
```

### 심각도

| | |
| --- | --- |
| `HIGH` | 비밀번호가 그대로 저장된다. 인증표를 확인하지 않는다 |
| `MEDIUM` | 나머지 |

## 5. 설정

### 볼 것

| 무엇 | 어떻게 찾나 |
| --- | --- |
| 어디서나 부를 수 있게 열어 뒀다 | 다른 주소의 요청을 모두 허용하는 설정 |
| 안전 설정이 없다 | 보안 관련 응답 설정이 하나도 없는 경우 |
| 오류 내용이 그대로 나간다 | 오류가 났을 때 내부 내용을 그대로 응답에 담는 경우 |
| 시험용 경로가 남아 있다 | `test`, `debug`, `tmp` 가 든 경로가 그대로 있는 경우 |
| 안전하지 않은 연결을 허용한다 | 암호화하지 않은 연결로도 들어올 수 있는 경우 |
| 배포 설정 파일에 비밀값이 있다 | `docker-compose*.yml` · `Dockerfile` · `*.tf` · `k8s/*.yaml` · CI 설정(`.github/workflows` 등)에 적힌 비밀번호 · 열쇠 · 개인 키 |
| 배포 설정이 위험하다 | 오래되었거나 지원이 끝난 이미지 버전, 관리용 포트(DB · 캐시)가 밖으로 열림, 모든 주소에서 들어오게 연 방화벽 규칙 |
| 자료 파일에 민감한 값이 있다 | 저장소에 든 `*.yml` · `*.json` · 시드 파일에 실제처럼 보이는 계정 · 비밀번호 · 보안 질문 답 · 열쇠 |

### 읽을 곳

설정 코드뿐 아니라 **저장소 맨 위와 배포 폴더의 설정 파일**(`docker-compose*`, `Dockerfile`, `*.tf`, `*.yml`), 시드 · 자료 파일.

### 이렇게 쓴다

```
좋음  오류가 나면 내부 정보가 그대로 보입니다
      어느 파일 몇 번째 줄에서 났는지까지 사용자에게 나옵니다

나쁨  CORS wildcard 설정. CSP 헤더 미적용
```

### 심각도

대부분 `MEDIUM`. 오류로 열쇠나 개인정보가 나오면 `HIGH`.

## 6. 개인정보 암호화

법에서 암호화를 요구하는 항목이 있다. 여기서 발견하면 **보안이면서 위법 문제이기도 하다.** 분류는 `보안`으로 두고, 설명에 법 이야기를 함께 적는다.

### 볼 것

| 무엇 |
| --- |
| 비밀번호를 되돌릴 수 있는 방식으로 저장한다 |
| 주민등록번호를 그대로 저장한다 |
| 계좌번호나 카드번호를 그대로 저장한다 |
| 기록에 개인정보나 인증표가 그대로 찍힌다 |

### 이렇게 쓴다

```
좋음  주민등록번호가 그대로 저장되고 있습니다
      법에서 암호화를 요구하는 항목이라 그대로 두면 과태료 대상입니다

좋음  기록 파일에 회원 전화번호가 남습니다
      기록을 보는 사람이면 누구나 볼 수 있습니다
```

### 심각도

전부 `HIGH`. 법이 요구하는 항목이고 유출 시 되돌릴 수 없다.

## 7. AI 기능

앱이 AI 모델(OpenAI · Anthropic · Gemini 등)을 부르면 본다. 부르지 않으면 건너뛴다.

### 볼 것

| 무엇 | 어떻게 찾나 |
| --- | --- |
| 지시문이나 개인정보가 브라우저로 내려간다 | 시스템 지시문 · 고객 정보 · 열쇠가 화면 코드(`"use client"` 파일 · 브라우저 번들)에 들어 있는지 |
| 사용자 글이 지시를 바꿀 수 있다 | 사용자 입력을 지시문에 이어 붙이고, 그 답으로 할인 · 권한 · 결제 · 도구 실행 같은 **실제 동작**을 하는 곳 |
| AI 가 부르는 도구에 제한이 없다 | 모델이 고른 도구 · 주소 · 인자를 확인 없이 실행하는 곳. 사용자가 도구 서버 주소를 정할 수 있는 곳 |
| 호출에 상한이 없다 | 로그인 없이 또는 횟수 제한 없이 유료 모델을 부르는 경로 (`비용` 분류와 겹치면 한쪽에만 적는다) |

`securityGroup` 은 새로 만들지 않는다. 브라우저로 내려가는 것은 `SECRET`, 지시를 바꾸거나 도구를 부르는 것은 `INPUT`, 로그인 없이 부르는 것은 `ACCESS_CONTROL` 로 적는다.

### 심각도

| | |
| --- | --- |
| `HIGH` | AI 답으로 돈 · 권한 · 자료가 바뀐다. 열쇠나 개인정보가 브라우저로 나간다 |
| `MEDIUM` | 지시문만 드러난다. 도구 제한이 느슨하다 |

## 코드로 확인할 수 없는 것

아래는 **문제로 적지 않는다.** 「확인하지 못한 영역」에 넣고, 필요하면 물어볼 것으로 만든다.
